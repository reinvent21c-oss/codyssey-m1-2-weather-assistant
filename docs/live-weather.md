## B-1 Product 결정 — 대화 중심 MVP

기본 화면은 **브리와 대화**. 고정 UI 인사로 오늘 외출 시각을 물으며 인사는 GPT를 호출하지 않음. 채팅의 서울 오늘 시각 선택 → **날씨 확인**(날씨 API만 조회) → 간결한 예보 요약 → **브리에게 추천받기**(고정 질문과 검증된 `outing_at`으로 기존 `/api/chat`) → 말풍선 답변과 추가 질문 흐름을 사용함. 날씨 조회와 AI 호출은 별도 사용자 행동으로 분리함.

기존 상세 외출 준비 화면은 보조 탭으로 유지. 브리 캐릭터·말풍선·하늘색/민트 색상 및 과거 365일 관측 데이터 조회·CRUD·차트·대화 저장/조회는 유지함. 자연어 시각 추출·GPS·전국 예보·자율형 Agent는 범위 밖임.

- 요약은 선택 시각/실제 예보 시각, 시각 차이, 기온·강수확률·예보 강수량·풍속, Open-Meteo/CC BY 4.0 출처와 서버 조회 시각을 표시. 모델 발표 시각은 미확인으로 구분함.
- 시각 변경·실패·응답 중 시각 변경·캐시 만료·외출 시각 도달 시 두 화면의 이전 요약과 검증 상태를 지움. 유효 예보가 없으면 추천 버튼을 비활성화하고 한국어 이유를 표시함.
- 응답의 `valid_until`은 서버 캐시의 남은 유효기간과 선택 시각 중 빠른 시각. 브라우저는 이 값과 조회 후 10분·선택 시각을 함께 검사하고 타이머 및 화면 복귀/전송 시 재검증함. 클라이언트 시계는 보조 검사이며 서버가 최종 판단함.
- 추천 버튼은 기존 채팅 전송·로딩·중복 방지·오류 처리·질문 보존을 재사용함. HTTP 429나 AI/저장 실패에 자동 재요청하지 않음. 전체 GPT 한도는 기존 10분당 5회 설정을 유지함.
- 평가자는 매 질문이 독립 대화이며 이전 질문을 기억한다고 안내하지 않음. 관리자는 기존 대화를 이어갈 수 있음.

## 날짜·단위·추천 규칙

- 오늘 날짜는 서버 OS 시간대가 아닌 서울 시간으로 계산. 현재 서울은 DST 없는 UTC+09:00이며 Windows tzdata 설치 없이 명명된 고정 오프셋을 사용함. 과거 시간대 변환 기능은 제공하지 않음.
- 현재 시각 이전의 선택은 거부. 정각은 해당 시간, 정각 사이의 분은 다음 정각으로 매핑. 예: 10:30 → 11:00(30분 차이), 오늘 23:30 → 다음 날 00:00. 선택 날짜는 항상 오늘이며 최대 차이는 59분. 내일의 임의 시각 선택은 지원하지 않음.
- 제공자 요청 범위는 서울 기준 오늘과 다음 날. 응답 timezone/UTC offset, 시간 배열 순서·중복·형식, 필드 길이, 단위와 유한 숫자 범위를 검증. bool·문자열·null·NaN·Infinity·결측 필드를 0으로 바꾸지 않음.
- 기온 °C, 강수확률 %, 예보 강수량 mm, 풍속 m/s 네 값이 모두 유효할 때만 추천. 미확인 값이 하나라도 있으면 전체 추천을 확인 불가로 처리하는 보수적 정책임.
- 강수확률과 강수량은 해당 정각 **이전 한 시간**의 예측값. 실제 관측 강수량이 아님. 기온·풍속은 해당 정각의 값. 한 시점/구간만 다루므로 외출 전체 시간의 날씨를 보장하지 않음.
- 기온별 기본 복장 구간: 5°C 미만 / 12°C 미만 / 20°C 미만 / 28°C 미만 / 그 이상. 강수확률 40% 이상 또는 예보 강수량 0 초과면 우산 권장. 10 m/s 이상이면 바람막이와 강풍 시 우산 주의 안내. 이는 브리의 일반 준비 규칙이며 의학·재난 판단 기준이 아님.

## 호출·캐시·실패 경계

- 서버 애플리케이션 인스턴스별 공유 10분 메모리 캐시와 잠금으로 동시 중복 호출 방지. 날짜 변경 시 새 날짜 조회. HTTP 각 단계 타임아웃 5초, 자동 재시도 없음, 리다이렉트와 환경 프록시 사용 안 함.
- 실패 뒤 10분 재시도 억제. 캐시 만료·날짜 변경 후 실패하면 오래된 값을 대신 보여주지 않음. 선택 시각 변경·재조회·실패 때 UI의 이전 추천도 제거.
- 캐시 기준 통상 인스턴스당 하루 약 144회와 날짜 변경 시 추가 조회 정도. 프로세스 재시작·다중 worker·복제본에는 공유되지 않으므로 제공자 계정/전체 IP 쿼터의 절대 상한은 아님. 규모 확장 전 분산 캐시/전역 제한 검토 필요.
- 호출 URL·서울 좌표 고정, 인증 헤더나 사용자 입력 URL을 제공자에 전달하지 않음. 제공자 오류 내용은 화면에 노출하지 않음.
- 실패·빈 결과·미지원 시각 응답은 HTTP 200의 `status: unavailable`, null 기상/추천 필드와 한국어 안내. 인증 실패는 기존 401 유지.

## GPT 연결

날씨 확인 성공 후 명시적인 추천 또는 질문 전송 시 선택한 aware timestamp(`outing_at`)만 전달함. 서버가 당일 날짜·분 단위 시각을 확인하고 **유효한 서버 캐시만** 읽어서 GPT Context로 전달함. 클라이언트 기상 수치 입력은 스키마에서 금지함.

채팅은 새로운 날씨 HTTP 요청을 만들지 않음. `outing_at`이 있으나 캐시 없음/만료/다른 날짜/이미 지난 시각이면 **HTTP 412로 거부하여 GPT 한도 소비·호출·대화 쓰기를 하지 않음**. 화면은 요약과 검증된 시각을 지우고 재확인을 안내함. 일반 질문은 유효한 날씨가 없으면 Context 없이 기존 과거 통계 채팅으로 보낼 수 있으며, 현재 날씨 수치를 추측하지 않도록 기존 프롬프트를 유지함. 유효한 Context는 오늘 예보이며 과거 365일 관측 통계·이전 대화의 수치와 구분함. GPT 제한·관리자/평가자 권한·저장 흐름은 유지함.
